# Спецификация: Дизайн-стандарты портала

Жёсткие правила оформления. **Любая UI/UX-задача (страница, компонент, письмо, анимация) обязана следовать этому документу и актуальным трендам из источников ниже.**

## Обязанность: всегда сверяться с актуальными источниками

Перед любой дизайн-задачей (или если результат «не впечатляет») — **сначала** посмотрите/поищите в интернете лучшие практики и тренды, а потом проектируйте:

1. https://cursor.directory/plugins?tag=rules — правила (`uiux-design`, `front-end`, `web-development`, `htmlandcss`)
2. https://mcpmarket.com/leaderboards — топ MCP (дизайн: Superpowers, Figma Context, Magic)
3. https://mcpmarket.com/tools/skills/leaderboard — топ Skills
4. Поиск в интернете: «лучшие практики дизайна [тип интерфейса] [год]», «web design trends 2026», «email design best practices 2026»
5. MDN Web Docs + W3C — база по HTML/CSS/доступности

Не проектируйте «из головы», если можно за 1-2 минуты найти актуальный референс и сделать лучше.

## Базовые принципы (из uiux-design)

**Visual Design**
- Чёткая визуальная иерархия, направляющая внимание пользователя.
- Целостная палитра в духе бренда (у школы фирменный `#2563eb`, см. `Base.astro`).
- Типографика ради читаемости и акцентов.
- Достаточный контраст (WCAG 2.1 AA).
- Единый стиль во всём приложении.

**Interaction & UX**
- Интуитивная навигация, знакомые UI-компоненты.
- Ясные CTA, направляющие поведение.
- Адаптивность на всех устройствах.
- Анимации — сдержанно, для пользы, не ради эффекта.
- Обратная связь на действия: лоадеры, понятные ошибки и пути восстановления.

**Доступность (a11y)**
- WCAG-гайдлайны; семантичный HTML (header/main/footer/article/section/nav/aside).
- alt для изображений; клавиатурная навигация; видимые focus-состояния.
- Контраст текста — всегда.

**Mobile-first**
- Проектировать под мобильные сначала, затем масштабировать вверх.
- Тач-цели минимум 44×44 px; комфортные промежутки.
- Content-first: главное — на первом экране; прогрессивное раскрытие; off-canvas для вторичного.

## Технические правила (из htmlandcss)

- Семантические элементы; `<button>` для кликов, `<a>` с href для ссылок, `<img>` с alt.
- Стили — через CSS (у нас — `<style>` в Astro-компонентах), не inline.
- Flexbox и Grid для раскладки.
- `rem`/`em` для шкалируемой типографики; CSS-переменные для тем (заданы в `Base.astro`).
- Медиа-запросы mobile-first; breakpoints по контенту, не по устройствам.
- Без `!important` (специфичность); без устаревших элементов.
- Ленивая загрузка изображений и медиа; оптимизация ассетов; минимум анимаций.
- `srcset`/`sizes` для адаптивных изображений.

## Правила для писем (email)

Письма верстать **таблицами** (flexbox/grid ломаются в почтовых клиентах), только inline-стили, широкие клиентские fallback. Проверять в Gmail/Outlook. Тренды искать по «email design best practices 2026».

## Проверка результата

- `npm run check` — типы и сборка обязательны без ошибок.
- Проверка в браузере на мобильном и десктопе (и devtools на отзывчивость).
- Быстрая самопроверка: иерархия? контраст? CTA? адаптив? анимации не мешают? ru/kk пары созданы?
